# ADR-0004. Импорт через промежуточную зону с отчётом о сопоставлении

- **Статус:** предложено
- **Дата:** 25.09.2026

## Контекст

В выпуске 2026 года текущий сервис молча потерял студентов (ИТСм-21: 13 → 11, ИСТ-43: 7 → 6) из-за буквы-двойника в ФИО и расхождения списков, а в приложения попал профиль вместо направления подготовки (см. [BACKLOG.md](../../BACKLOG.md): B-01, B-03, B-25). Сопоставление по одной фамилии может перепутать однофамильцев (B-02). Все эти ошибки возникают на стыке файлов из разных источников.

## Решение

- Импорт никогда не пишет сразу в картотеку. Загруженные данные попадают в промежуточную зону импорта.
- Этапы: распознавание макета → нормализация (пробелы, латинские двойники, даты, коды оценок) → сопоставление (студенты по «Фамилия И. О.», дисциплины по элементам учебного плана) → отчёт → подтверждение пользователем → запись в картотеку и журнал аудита.
- Отчёт показывает четыре группы: «совпало», «нет в ведомостях», «нет в сведениях», «неоднозначно». Пока есть несовпадения, подтвердить импорт нельзя: пользователь исправляет файл или вручную связывает записи.
- Каждое значение хранит ссылку на источник (файл, лист, строка) для прослеживаемости.
- Входные форматы подключаются адаптерами: ведомости «Деканата», учебный план, сведения о студентах, XML КиберДиплома 3.5.1.

## Последствия

- Молчаливая потеря записи становится невозможной по построению.
- Импорт занимает на один шаг больше — пользователь просматривает отчёт.
- Правила разбора из `python-engine/app/parser.py` переносятся вместе с тестами и становятся адаптером ведомостей.

## Отвергнутые варианты

- **Прямая запись с предупреждениями в журнале (как сейчас):** предупреждения никто не видит.
- **Ручной ввод без импорта:** слишком трудоёмко для выпуска в сотни человек.
