# ADR-0001. Модульный монолит «локальный веб», один исполняемый файл, два режима

- **Статус:** предложено
- **Дата:** 25.09.2026

## Контекст

Система должна работать и на одиночном компьютере без сети, и на сервере вуза для многих пользователей (R1), на Windows 7–11 и российских Linux (R2), без Docker и предустановленных рантаймов (R3). Текущий сервис — три процесса на двух языках в Docker — на такие машины не ставится.

## Решение

Одно приложение — модульный монолит — с встроенным веб-сервером и интерфейсом в браузере.

- Настольный режим: сервер слушает `127.0.0.1`, данные в файле SQLite, при запуске открывается браузер.
- Серверный режим: тот же исполняемый файл слушает сеть, данные в PostgreSQL, включены учётные записи и роли.
- Модули (справочники, учебные планы, импорт, картотека, проверка, печать, экспорт, аудит, доступ) разделены внутри кода явными границами и не обращаются к таблицам друг друга напрямую.
- Интерфейс — HTML, собранный на сервере, с минимальным JavaScript; совместим с Chrome 109 и Firefox ESR 115.

## Последствия

- Установка — распаковать и запустить; обновление — заменить один файл.
- Один процесс проще сопровождать силами кафедры, чем набор сервисов.
- Интерфейс ограничен возможностями старых браузеров: без тяжёлых SPA-фреймворков.
- Печать идёт через PDF и браузер, а не напрямую в драйвер принтера (см. ADR-0003).

## Отвергнутые варианты

- **Микросервисы в Docker (как сейчас):** Docker недоступен на Windows 7, 32-битных системах и во многих закрытых контурах Astra.
- **Нативное настольное приложение:** нет серверного режима «бесплатно»; кроссплатформенный GUI для Windows 7 (32 бит) и Astra дорог.
- **Только облачный/серверный веб:** не покрывает одиночный компьютер без сети.
