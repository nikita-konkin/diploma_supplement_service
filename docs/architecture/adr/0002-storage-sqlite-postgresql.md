# ADR-0002. Хранение: SQLite в настольном режиме, PostgreSQL в серверном

- **Статус:** предложено
- **Дата:** 25.09.2026

## Контекст

В настольном режиме нельзя требовать установки СУБД. В серверном режиме нужны одновременная работа нескольких пользователей, резервное копирование штатными средствами и привычная администраторам вуза СУБД. PostgreSQL (и её российские сборки) входит в репозитории Astra Linux, РЕД ОС и Альт.

## Решение

- Настольный режим: один файл SQLite в папке данных.
- Серверный режим: PostgreSQL.
- Код работает через общий слой доступа к данным; SQL ограничен подмножеством, одинаково работающим в обеих СУБД.
- Схема меняется только миграциями с номерами версий, которые применяются при запуске.
- Перенос данных из настольного режима в серверный — встроенная команда экспорта и импорта.

## Последствия

- Резервная копия в настольном режиме — копия файла; в серверном — `pg_dump`.
- Нельзя пользоваться возможностями, специфичными для одной СУБД (например, типами массивов PostgreSQL), без обходного пути для SQLite.
- Тесты слоя данных прогоняются на обеих СУБД.

## Отвергнутые варианты

- **Только PostgreSQL:** требует установки и администрирования на каждом рабочем месте.
- **Только SQLite:** не подходит для одновременной работы многих пользователей по сети.
- **Файлы Excel/XML как хранилище:** нет целостности, журналирования и одновременного доступа.
