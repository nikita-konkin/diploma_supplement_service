# Сервис автоматизации операций составления приложений к дипломам

[пгту-ртф.рф](https://xn----etb9agicel.xn--p1ai/)

Проект предназначен для генерации сводных таблиц на основе данных, а также создания XML-документов. Он состоит из нескольких модулей:

- `java-api` – Java-сервис, который предоставляет HTTP-интерфейс и служит фронтом для операций.
- `python-engine` – Python-движок для анализа и подсветки проблемных ячеек при создании сводных таблиц.
- `python-xml-engine` – Python-модуль, отвечающий за генерацию XML-документов.
- `python-attestation-engine` – отчёты об аттестации групп кафедры по данным портала РИТМ; отдельный компонент по адресу `/attestation` со своим входом.

## Запуск

Работа всех компонентов организована через Docker. Соберите и запустите контейнеры командой:

```sh
docker-compose up --build
```

Образы складываются из соответствующих `Dockerfile` в каталогах `java-api`, `python-engine` и `python-xml-engine`.

Сервисы взаимодействуют внутри общей сети, порты и переменные настраиваются в `docker-compose.yml`. Файл `.env` необязателен: пример настроек — в `.env.example`.

Тесты всех сервисов выполняются при сборке образов, упавший тест останавливает сборку (подробнее — в `TESTING.md`).

Внутри контейнеров:

- `java-api` — шлюз на Takes: отдаёт страницу, принимает файлы и пересылает запросы в движки.
- `python-engine` — прослушивает API для создания сводных таблиц.
- `python-xml-engine` — отвечает за генерацию XML-документов.
- `python-attestation-engine` — выгружает аттестацию из РИТМ и собирает краткий (ГОСТ) и подробные отчёты DOCX и отчёт Markdown.

## Функциональные разделы

### "Создать сводную таблицу"

1. Пользователь загружает исходный Excel-файл (или передает данные по API).
2. `java-api` пересылает задачу в `python-engine`, где выполняется анализ, подсветка проблемных ячеек и формирование итоговой сводной таблицы.
3. Особенности:
   - В движке происходит проверка и выделение ячеек с неконсистентными данными;
   - Результат возвращается в виде нового Excel-файла с выделениями и/или JSON, в зависимости от API.
   - Параметры конфигурации (например, критерии объединения) задаются через `Config` в Java и `settings` в Python.

### "Создать документ XML"

1. После получения данных для XML, `java-api` направляет запрос в `python-xml-engine`.
2. Этот движок строит XML на основе шаблона и данных, применяя дополнительные правила.
3. Особенности:
   - Генерация проходит в `app/xml_generator.py`, где содержатся нюансы формирования тегов и атрибутов;
   - В конфигурации можно менять структуру выходного документа;
   - Если данные некорректны, возвращается ошибка с описанием проблемных полей.

### "Отчёт по аттестации" (`/attestation`)

Отдельная страница, не вкладка главной: открывается по адресу `/attestation`. Пользоваться может любой преподаватель с учётной записью РИТМ.

1. Преподаватель входит логином и паролем портала РИТМ: пароль проверяет сам портал, сервис хранит только сеанс портала.
2. Выбирает учебный год, семестр, номер аттестации, кафедру (список из «Процента аттестаций по кафедрам»), факультет и направления групп своей кафедры («ИТС(о)», «ИСТм(о)» — направление и форма обучения).
3. `java-api` пересылает запросы в `python-attestation-engine`, который под учётной записью преподавателя выгружает «Аттестацию по выбранной группе» по группам выбранных направлений и «Процент аттестаций по кафедрам» и собирает отчёты.
4. Отчёт показывается на странице по разделам (сводка, группы, дисциплины, преподаватели), файлы DOCX и Markdown скачиваются.

Какие группы относятся к кафедре, в РИТМ не записано, поэтому выбор направлений запоминается для кафедры (в томе `attestation-data`) после первого удачного отчёта; новые группы тех же направлений попадают в отчёт сами. Для ИТРС заготовка встроена.

Защита:

- пароль РИТМ используется один раз для входа в портал и не сохраняется; сеанс портала живёт в памяти и забывается при выходе или после 30 минут бездействия;
- сеанс сайта — cookie `HttpOnly`, `Secure`, `SameSite=Strict` на путь `/attestation`; изменяющие запросы требуют CSRF-токен;
- неудачные входы ограничены (5 на адрес и 30 всего за 15 минут), после этого запросы на портал не отправляются — сайт нельзя использовать для подбора паролей РИТМ;
- выгрузка идёт под учётной записью преподавателя: в отчёт попадает только то, что портал показывает ему;
- пароли не попадают в журналы, выгруженные данные удаляются через `ATTESTATION_FILES_TTL` секунд (30 минут);
- заголовки CSP, `no-store`, `noindex`; сайт должен работать по HTTPS — cookie помечена `Secure`.

## Использование в Docker

Для контейнеризации доступны Dockerfile в каждом модуле. `docker-compose.yml` связывает сервисы между собой, устанавливает сети и порты.
